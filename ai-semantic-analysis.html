AI semantic analysis

Turning a raw diff into a plain-language explanation — and keeping that explanation honest.

What semantic analysis adds

Deterministic comparison always runs first and tells you exactly what changed. Turning on semantic analysis runs an AI layer on top of that deterministic result and adds, for each change:

  • An interpretation — a plain-language sentence describing what the change means (e.g. "The deadline changed from 30 to 15 days, shortened by 15 days.").
  • A type — one of requirement_change, value_change, deadline_change, obligation_change, permission_change, restriction_change, addition, removal, contradiction, breaking_change, or informational_change.
  • A severity and confidence score.
  • A verification result — see below.

Semantic analysis never rewrites the deterministic result — it only annotates it. The raw diff you'd get with semantic analysis off is always exactly what's underneath.

Analysis modes

The Analysis dropdown in the toolbar picks one of three modes:

  • Semantic + Lexical (default) — shows both the raw diff and the AI interpretation.
  • Lexical — skips the AI call entirely. Deterministic-only, no API key needed.
  • Semantic — the deterministic diff still runs behind the scenes (semantic analysis needs it to have something to annotate), but the UI hides the raw lexical diff and type/granularity badges in favor of the AI interpretation alone. This is often the more useful view for a PDF comparison, where character-level positions don't line up as cleanly with the source document.

Find-in-text stays available regardless of which mode you're in.

Choosing a provider

Open the gear icon (top right) to open Settings and pick which AI provider powers semantic analysis:

ProviderAPI key needed?Notes
Heuristic (default)NoA deterministic, rule-based classifier. No network call, no key, and results are stable across runs.
ClaudeYesUses Anthropic's models via forced tool use, so the response always matches the expected structure.
OpenAIYesUses OpenAI's models via forced function calling.
GeminiYesUses Google's models via forced function calling.

Each provider has its own model dropdown and API key field, and its own slot in your saved settings — switching providers never mixes one vendor's key into another's field. A status pill next to the Analysis dropdown always shows which provider/model is currently active, and doubles as a shortcut back into Settings.

If a real provider's response doesn't match the expected structure, or the request to that vendor's API fails (bad key, rate limit, network issue), the comparison fails loudly rather than silently falling back to a guess — you'll see an error instead of a quietly-wrong answer.

Where your API key goes

How your key is stored depends on whether you're signed in:

  • Signed in — your key is encrypted and stored against your account, so it's available the next time you sign in from any device. See Account & Settings for how to add, replace, or remove it.
  • Not signed in — your key stays only in your browser's local storage and is sent with each comparison request from that browser. It never leaves your device except in that request.

Either way, a key is only ever used for your requests, is never echoed back to you in full after you save it (Settings shows a short hint instead), and is only sent onward to the vendor you chose it for.

Custom instructions

The AI focus field next to the Analysis dropdown accepts free-text guidance (up to 2,000 characters) that's appended to every prompt for whichever real provider you've chosen — for example, "focus on pricing changes." It steers what the AI pays attention to, but never overrides the verification step below, and it's disabled in Lexical mode and ignored by the Heuristic provider, since neither makes an AI call to steer.

Verification: keeping the AI honest

Every interpretation — heuristic or from a real provider — passes through a verification step. DiffFind extracts the factual values an interpretation cites (numbers, percentages, dates, currency, identifiers, URLs) and confirms each one actually appears in that change's evidence or your source documents. If an interpretation references a value found nowhere in your source, it's flagged as unverified, with the offending value and a reason shown alongside it.

This is what keeps AI output trustworthy: a plausible-sounding but fabricated number gets caught rather than shown as fact, regardless of which vendor produced it.
