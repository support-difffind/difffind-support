Interactive docs

GET /openapi.json serves the full OpenAPI 3.0 document, generated from the same schemas that validate requests at runtime, so it can't drift from what the API actually accepts. GET /docs serves an interactive Swagger UI over that same document, where you can browse every endpoint's request/response shape and call /v1/compare directly from the page.

POST /v1/compare

The core endpoint. Compares before and after content and returns the changes.

curl -s -X POST https://app.diffind.com/v1/compare \
  -H 'Content-Type: application/json' \
  -d '{"before": "Payment is due within 30 days.", "after": "Payment is due within 15 days.", "options": {"semantic": true}}'

Key options fields:

FieldDefaultDescription
lexicaltrueRun deterministic comparison.
semanticfalseRun AI semantic analysis on top of the deterministic changes.
formatauto"text", "json", "yaml", "xml", or "csv".
caseSensitivetrueCase-sensitive comparison.
normalizeWhitespacefalseCollapse whitespace runs before comparing.
detectMovestrueBest-effort detection of relocated content.
llmheuristic{ provider: "heuristic" | "claude" | "openai" | "gemini", model?, apiKey? }
customInstructionsnoneFree-text guidance for the AI prompt (max 2000 chars). Ignored when semantic is false or the provider is heuristic.

JSON, YAML, XML, and CSV are compared structurally — the response's lexical.path is an RFC 6901 JSON Pointer (e.g. /timeout, or /0/age for a CSV cell) instead of a text range. See AI Semantic Analysis for what the semantic block on each change contains, including verification.

POST /v1/locate

Maps every RFC 6901 path a structural (json/yaml/xml) comparison can produce to the 0-indexed source line it occurs on, for both sides. This is what the app uses to jump a change card to its exact location; it's exposed as its own endpoint since it's useful to any client rendering its own view of a structural diff. 

curl -s -X POST https://app.diffind.com/v1/locate \
  -H 'Content-Type: application/json' \
  -d '{"before": "{\"timeout\": 500}", "after": "{\"timeout\": 200}", "granularity": "json"}'

Returns null for either side when granularity isn't "json"/"yaml"/"xml", or when that side failed to parse — treat either as "no exact location available." CSV isn't covered by this endpoint yet.

POST /v1/load

Fetches document content server-side for use as compare input — either a GET request to a URL, or a full curl command.

curl -s -X POST https://app.diffind.com/v1/load \
  -H 'Content-Type: application/json' \
  -d '{"source": "url", "url": "https://api.example.com/config"}'
This endpoint fetches whatever URL or curl command it's given. Treat it like any other server-side-fetch surface: only point it at sources you trust, and don't build an integration that lets untrusted input reach it unfiltered.

POST /v1/format

Pretty-prints JSON/YAML/XML/CSV content. Best-effort: content that isn't valid for its format comes back unchanged with changed: false rather than an error.

curl -s -X POST https://app.diffind.com/v1/format \
  -H 'Content-Type: application/json' \
  -d '{"content": "{\"a\":1,\"b\":2}"}'

GET /health

Liveness check: { "status": "ok", "uptimeSeconds": 12.3 }.

Agent-operable tools

Beyond the raw HTTP API, DiffFind exposes the same engine as a small set of typed, agent-operable tool functions with no hidden state — the shape an MCP server would wrap directly:

  • compareText({ before, after, options }) — forces text-mode comparison.
  • compareDocuments({ before, after, options }) — auto-detects text vs. JSON/YAML/XML/CSV.
  • findMaterialChanges({ before, after }) — "Did anything materially change?"
  • detectBreakingChanges({ before, after }) — "Did this introduce a breaking change?"
  • findDeadlineChanges({ before, after }) — "Did any deadlines change?"
  • findNumericalChanges({ before, after }) — "Did any numerical requirements change?"
