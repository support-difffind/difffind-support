Supported formats

DiffFind compares Text, JSON, YAML, XML, CSV, and PDF (via the File loader). Format is auto-detected — JSON is checked first, then XML, then YAML, then CSV, falling back to plain text — or you can force one with the Format dropdown.

JSON, YAML, XML, and CSV are all compared structurally, not as raw text: each is parsed into a value tree and the trees are diffed against each other. That means:

  • Reordering object keys never shows up as a change.
  • Reformatting (indentation, quoting style, line breaks) never shows up as a change.
  • Every change carries a path to exactly where it happened — for example /server/limits/maxConnections for JSON/YAML/XML, or /3/price (row 3's price column) for CSV.

Even when you paste JSON/YAML/XML/CSV, you still get the line-numbered inline diff view too — it always runs its own plain-text comparison alongside the structural one, so you get both views without switching the Format dropdown.

Comparison options

OptionDefaultWhat it does
Case sensitiveOnTreats differently-cased text as a change.
Normalize whitespaceOffCollapses whitespace runs before comparing, so whitespace-only differences don't show up as changes.
Detect movesOnBest-effort detection of content that was relocated rather than edited, shown as its own change type.
FormatAutoForces Text / JSON / YAML / XML / CSV instead of auto-detecting.

Every option — plus the Analysis mode and the Show filters below — is remembered in your browser and restored the next time you visit. Reset in the toolbar clears everything, including Before/After content, back to defaults.

Loading content: URL, curl, and File

Each Before/After panel has a loader dropdown next to it:

  • Plain (default) — type or paste directly into the textarea.
  • URL — runs a GET request and loads the response body. This happens server-side, so the target doesn't need to allow cross-origin requests from DiffFind.
  • curl — paste a full curl command (e.g. curl -X POST '...' -H '...' -d '...'); it's parsed and executed server-side, and the response body becomes your comparison input.
  • File — reads a local file directly in your browser (no server round trip), including .pdf files — see Comparing PDFs.
URL and curl loading fetch whatever address you give them, from DiffFind's server. Only point them at URLs and commands you trust — don't paste one you got from someone else without checking it first.

Pretty print

The Pretty print checkbox in the toolbar reformats minified JSON/YAML/XML/CSV into readable, indented text — useful right after a curl/URL load, which often arrives as one unreadable line. Checking it reformats whatever's currently in Before/After and keeps auto-reformatting anything loaded afterward while it stays checked. Unchecking it restores each side's exact original content — nothing is lost, only hidden while formatted. It's disabled when Format is forced to Text, and it's a no-op on content that isn't valid for its format.

Comparing PDFs

Pick a local .pdf via the File loader and DiffFind renders it in your browser, extracts the text from every page, and compares that extracted text exactly as if you'd pasted it directly. PDF loading is File-only — URL/curl sources don't support PDFs.

When both Before and After are PDF-sourced, Compare draws the diff directly on the rendered pages instead of the usual text view: each changed word or phrase is highlighted right where it appears (red on Before, green on After, gray for a detected move). The change cards below still show each change's type and AI interpretation, but the line-based inline diff pane is hidden for this case, since extracted PDF text has no real line structure to show there. Comparing one PDF against typed or pasted text keeps the normal text-diff view.

Find-in-text and the scroll-sync minimap both work the same way against rendered PDF pages as they do against plain textareas.

The inline diff view

After a comparison, the inline diff renders your full Before/After documents side by side, line-numbered. Every changed line gets a light full-row tint (red on the left, green on the right), and within that line, a character-level diff darkens only the exact characters that differ — so "price": 159.0 → "price": 179.0 tints the whole line but darkens only the digit that changed. Pure additions/deletions and moved text get their own highlight colors, called out in the legend above the view.

The two panes scroll together, each keeping its own scrollbar. A thin minimap next to each pane shows a tick for every changed line at its true position in the document, plus a rectangle for your current viewport — click anywhere in it to jump straight there. Both the textareas and the diff panes also have a shared drag handle underneath them to resize both sides of a pair together, in addition to each element's own native corner-resize.

Change cards and jump-to-line

Each change card shows the line(s) it occurs on and is clickable — clicking scrolls both inline panes to that change with a brief highlight flash. Text changes jump to their exact line; structural (JSON/YAML/XML) changes are mapped from their path to a source line automatically, so the jump lands correctly even when a field name or value repeats elsewhere in the document. CSV changes carry a path too, but don't yet get a clickable line number.

A small ▾ / ▸ toggle on each card collapses its old/new values and semantic detail, leaving just the type/severity badges — the click-to-locate behavior still works while collapsed.

The Show filter bar (Additions / Deletions / Modifications / Moves) hides a type's cards and its highlighting in the inline panes together, so the two views never disagree about what's shown. The summary counts above it always reflect the full, unfiltered comparison.

Finding text before you compare

The find bar above the two panels searches the raw text you're about to compare — not the results — and highlights matches directly over the Before/After content as you type. A scope selector (Both / Before / After) controls where it searches: with a single side selected you get one running match count with Previous/Next; with Both, each side tracks its own match and count, and Previous/Next steps them together in lockstep. This is entirely client-side — nothing is sent to the server.

History

The History dropdown recalls your last 10 unique comparisons, stored in your browser. Picking a past entry restores each side the way it was originally loaded — plain text is set directly, a file's cached content is restored, and a URL/curl entry re-runs that same load fresh rather than replaying stale output. If Pretty print reformatted a side, history keeps what you actually typed or loaded, not the reformatted version. Re-running an identical pair moves the existing entry to the top instead of duplicating it, and Clear history empties it.
